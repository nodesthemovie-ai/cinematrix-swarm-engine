**Template:**
```

- Help you work around it immediately, OR
- File it as a GitHub issue for the team

3. What was your input premise? (genre, budget range, etc.)
4. What was the exact error message you saw?

Once I know these details, I can either help you work around it or we'll 
create a GitHub issue to track it.

Thanks for your patience!
```

## Response Strategies

### General Best Practices

1. **Respond within 24 hours** when possible
2. **Start with acknowledgment** of their specific point (not generic)
3. **Be genuine** — your authentic voice matters
4. **Answer their question directly** before anything else
5. **Keep it brief** — 2-3 paragraphs max for most responses
6. **End with invitation** — ask them to try something or give feedback
7. **Use their platform** — reply on Twitter, LinkedIn, Discord, etc. where they commented

---

### Tone Guidelines

**Maintain:**
- Friendly but professional
- Enthusiastic but not salesy
- Helpful and generous
- Open to feedback and criticism
- Community-focused (not corporate)

**Avoid:**
- Generic responses (always personalize)
- Over-explaining (less is more)
- Defensiveness (embrace feedback gracefully)
- Spam-like language or emojis overuse
- Corporate jargon

## Difficult Engagement Responses

### For Criticism/Negative Feedback

**Template:**
```
You raise a fair point about [specific criticism]. 

Here's how we think about it: [Genuine explanation of design decision]

That said, [acknowledge any validity to their concern] — and that's exactly 
the kind of feedback we use to improve.

Would be curious what would make this better for your use case.
```

**Example:**
```
You raise a fair point about the system prompt being long. 

We built it that way intentionally because each constraint/instruction matters 
for preventing hallucinations and paradox outputs. But I hear that it's a 
friction point.

That's exactly the kind of feedback we'll use for v1.2.0 — maybe a "quick 
start" simplified version plus the full version for advanced users.

What would make this easier for you?
```

---

### For Skeptical/Dismissive Comments

**Template:**
```
Fair skepticism! This is genuinely new territory.

[One sentence validating their concern]

What I'd suggest: [Low-friction way to test the claim]

Then you'll have direct experience rather than my pitch. Would be curious 
what you find!
```

**Example:**
```
Fair skepticism — AI generating "creative" work is still pretty experimental!

The question we solve is different though: not "Can AI be creative?" but 
"Can AI help you think like a producer/cinematographer/screenwriter when 
you're developing your own ideas?"

Try it with your own premise and see if the perspectives are useful, even if 
the specific outputs aren't perfect. That's how most people find value.

Let me know what you think!
```
