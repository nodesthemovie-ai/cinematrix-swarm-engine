## Scoring Tips

Devpost judges look for:

✅ **Innovation:** Novel approach to problem (multi-agent in creative domain)  
✅ **Completeness:** Functional, polished, documented system  
✅ **Usefulness:** Real world application (film industry + education)  
✅ **Presentation:** Clear communication of what it does  
✅ **Technical Depth:** Smart architecture (zero-trust, coordination)  
✅ **Community:** Open source, welcoming to contributors  

**CineMatrix Strengths for Judging:**
- Unique domain (AI + filmmaking)
- Clean, understandable architecture
- Production-ready documentation
- Real use cases (professionals, students, creators)
- Open source from day 1

## Common Devpost Q&A

**Q: Do I need a video?**  
A: Not required, but highly recommended. Videos get ~30% more engagement.

**Q: Can I update after submission?**  
A: Yes! You can edit your project until the hackathon ends.

**Q: Should I include my GitHub in description?**  
A: Yes, put it in the links section AND mention it in description.

**Q: How long should description be?**  
A: 3-5 paragraphs is ideal. Long enough to be complete, short enough to read.

**Q: Any special formatting for Devpost?**  
A: Markdown works (bold, lists, code blocks).
